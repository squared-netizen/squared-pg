## Content

`squared-pg` is the canonical offline-first project generator for applications
built on the Squared framework.

The repository is divided into:

```text
engine/       the C++20 engine: capability, no policy
engine/lua/   the generated binding layer
app/          sqpg, the reference CLI host
lua/          the control layer: workflows and modules
resources/    templates, kits, packages, assets
sqcart/       the cartridge library, vendored from source
third-party/  vendored dependencies
tools/
docs/
```

The root contains the project-wide build configuration and project
documentation.

Two of these sit awkwardly and are worth naming explicitly, because the
question "why is that there" has an answer:

- **`app/` is a consumer of the engine, not part of it.** `sqpg` is the
  reference host, and one host among possible others; the C++ API is the
  architectural boundary, not the command line ([[2.1 Architectural model]]).
  An engine that could not be driven by a different host would have the
  boundary in the wrong place.
- **`engine/lua/` is generated from the operation registry and committed.**
  It is the only directory in the repository where "this is checked in" and
  "do not edit this by hand" are both true. Committed rather than generated at
  build time, so the tree is readable without building it; a hand edit is lost
  on the next regeneration.

Note the distinction from `lua/`, which is the opposite: hand-written, shipped
as a resource, and the thing a user edits to change how the generator behaves
without recompiling. That is why Lua is in the project at all.

`sqcart/` is a self-contained companion project with its own build and test
harness, vendored from source. `squared-pg` links it and never acquires it as
a cartridge ([[1.11 Dependency direction]]).

`docs/spec/` is the functional specification vault, part of `docs/`
([[1.8 Documentation]]).
