## Content

> [!warning] Status
> The `resources/` tree is planned but **not yet provisioned** in the
> repository. The namespaces below are the target design; nothing places files
> there until the tree is created. This section is accordingly marked `draft` — it
> describes intent, not what currently exists on disk
> (see [[1.1 Repository identity]]).

`resources/` is intended to contain data consumed by the generator.

Its namespaces are:

```text
resources/assets/
resources/generator/
resources/kits/
resources/packages/
resources/templates/
```

These namespaces MUST remain semantically distinct:

- `assets/` — reusable application/runtime assets **for generated projects**.
  This is an Android-style application asset tree and holds the default assets
  materialized into generated projects.
- `generator/` — resources `squared-pg` consumes **for itself**: tooling data,
  generator iconography, internal fixtures. Generator resources MUST NOT be
  materialized into a generated project.
- `kits/` — project-generation kits and their metadata.
- `packages/` — versioned reusable packages of the Squared framework.
- `templates/` — project and application templates.

A resource MUST NOT be placed in another namespace merely because doing so is
convenient for implementation.

Miscellaneous reusable data belonging to no namespace lives at the `resources/`
root.

Every resource under `templates/`, `kits/`, `packages/`, and `assets/` MUST carry
a `manifest.json` at its root. The physical directory layout beneath these
namespaces is an implementation detail and MUST NOT form part of any public
contract — resources are addressed by identity, never by path
(see [[2.10 Assets and generator resources]]).
