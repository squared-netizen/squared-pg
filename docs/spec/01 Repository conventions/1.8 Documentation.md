## Content

`docs/` contains project documentation and specifications, divided into:

```text
docs/index.md       entry point / landing page
docs/programmer/    API consumers
docs/developer/     engine maintainers
docs/spec/          the functional specification (this vault)
docs/edu/           educational material
docs/history.md     project history
docs/todo.md        planning material
```

`docs/index.md` serves as the documentation landing page; the `programmer/` and
`developer/` trees are planned and not yet populated.

### The two normative documentation trees

`squared-pg` MUST maintain two parallel, cross-linked documentation trees.

**`docs/programmer/`** — for people using the generator and its APIs. Documents
every public-facing symbol: purpose, parameters, return values, pre- and
postconditions, error conditions, a minimal usage example, and the Lua-side
equivalent where bound. It MUST NOT contain internal implementation detail,
private members, or data-structure internals.

**`docs/developer/`** — for people maintaining or extending the generator.
Documents implementations: how each subsystem works, which data structures and
algorithms were chosen and why, the complexity characteristics that motivated
them, every design pattern used and the alternatives rejected, architectural
decisions, invariants, the ownership and threading model, and known limitations.

Both trees are organized by subsystem with a top-level index, mirror each other's
module structure, and cross-link where a topic appears in both.

Any change touching a public API or a significant internal implementation MUST
update the relevant pages in the same change. Documentation is not a follow-up
step.

### Specification

The functional specification lives at `docs/spec/` and is maintained as an
Obsidian vault. It is normative: where the specification and an implementation
disagree, one of them is a defect.

Specifications and documentation SHOULD be Markdown so they remain usable offline
and compatible with the project's Obsidian-oriented workflow.
