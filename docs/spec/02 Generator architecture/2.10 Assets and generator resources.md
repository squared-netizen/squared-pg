## Content

### 2.10.1 Resource storage

Generator resources live under `resources/` ([[1.5 Resources]]):

```text
resources/assets/      application assets for generated projects
resources/generator/   resources squared-pg consumes for itself
resources/kits/
resources/packages/
resources/templates/
```

> [!note] Resolution of Q-18 (D-018)
> The earlier draft defined a "generator assets" category with no home.
> `resources/generator/` is that home. Resources under it are **generator-owned
> and MUST NOT be materialized into a generated project**. `resources/assets/`
> remains project-bound only.

`resources/assets/` is an Android-style application asset tree, per the project
vision: it holds the default application assets materialized into generated
projects, including the default Android assets.

Physical layout beneath any namespace is a maintainer convenience and MUST NOT be
part of a contract. Every resource is addressed by identity.

### 2.10.2 Asset categories

| Category | Provided by | Ends up | Owned after generation by |
|---|---|---|---|
| Generator | `resources/generator/` | never in a project | generator |
| Framework | packages | project | project |
| Kit | kits | project | project |
| Application | `resources/assets/` | project | user |

The generated project MUST distinguish these. A generator-owned resource MUST NOT
silently become a user-editable application asset.

### 2.10.3 Asset manifest block

```json
"asset": {
  "asset_type": "texture",
  "format": "png",

  "source": "player.png",

  "target": {
    "android": "assets/textures/player.png",
    "desktop": "resources/textures/player.png"
  },

  "transform": {
    "android": "texture.compress.etc2",
    "desktop": "copy"
  },

  "requires_packages": ["package.squared.graphics"],

  "class": "seeded",

  "integrity": {
    "algorithm": "sha256",
    "value": "…"
  }
}
```

### 2.10.4 Asset type vocabulary

`asset_type` is drawn from a closed vocabulary so the engine can validate and
route without interpreting file contents:

```text
texture   audio   font   shader   model
data      locale  script  binary
```

`binary` is the escape hatch: an opaque payload copied without interpretation. It
MUST NOT be used to smuggle a type that has a proper vocabulary entry.

### 2.10.5 Transformation

A transformation is an engine capability token
([[2.14 Extensibility model]]). The manifest names a transformation per platform;
`copy` is the identity transformation.

```text
source asset -> transform -> platform resource
```

Transformations MUST be deterministic: identical source, settings, and engine
version MUST produce equivalent output, and SHOULD produce byte-identical output
where the transformation is not timestamp- or ordering-sensitive.

A transformation whose capability is unavailable MUST fail at **resolution**,
never at materialization — the workflow must learn it cannot proceed before
anything is written.

*Pattern: Strategy, keyed by asset type and target platform.*

### 2.10.6 Platform placement

`target` maps platform to workspace-relative destination. The template and applied
kits determine which platforms are active; the Asset Service MUST NOT assume a
universal layout.

An asset with no `target` entry for an active platform is skipped, and the skip
MUST be reported as a diagnostic rather than passing silently.

### 2.10.7 Integrity

Assets SHOULD declare an `integrity` digest. Where declared, the Resource Service
MUST verify it before the asset enters generation, and MUST fail with
`asset.integrity` on mismatch.

This is what makes an offline resource tree trustworthy after being copied,
archived, or restored.

### 2.10.8 Ownership

During generation the engine owns resolved asset state, transformation state,
temporary files, and staging resources. After finalization the project owns
materialized application assets.

Materialized asset paths carry an ownership class exactly as template paths do.
Application assets are `seeded` by default: the generator seeds them once and the
user owns them thereafter.

### 2.10.9 Validation

Assets MUST be validated for envelope correctness, identity and version syntax,
asset type validity, source availability, integrity where declared,
transformation availability, target declarations for active platforms, and
package requirements.

Invalid assets MUST NOT silently enter the pipeline.
