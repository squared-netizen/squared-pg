## Content

### 2.11.1 What a package is

A package provides reusable Squared framework functionality: C++ sources, public
headers, libraries, build targets, configuration, framework services, runtime
resources, tests, and documentation.

A package MUST expose functionality through documented public interfaces and MUST
NOT require the generator to understand its private implementation. A package
MUST NOT redefine the architectural role of the selected template.

```text
Template  = project foundation
Kit       = external framework / platform bridge
Package   = reusable Squared functionality
Asset     = project data
```

### 2.11.2 Package manifest block

```json
"package": {
  "provides": ["graphics-api", "rendering-services"],

  "supported_templates":  ["*"],
  "supported_kits":       ["kit.sdl3", "kit.android"],
  "supported_platforms":  ["desktop", "android"],
  "supported_framework":  "^1.0",

  "features": {
    "vulkan": { "default": false, "requires_platform": ["android", "desktop"] },
    "opengl": { "default": true }
  },

  "build": {
    "target": "Squared::Graphics",
    "kind": "static",
    "sources": ["src/**.cpp"],
    "public_includes": ["include"],
    "link": ["Squared::Core"],
    "definitions": { "SQ_GRAPHICS": "1" }
  },

  "files": [
    { "path": "external/squared/graphics/**", "class": "generated" }
  ],

  "integrity": { "algorithm": "sha256", "value": "…" },

  "migrations": [
    { "from": "^1.0", "to": "2.0.0", "rules": "migrations/1-to-2.json" }
  ]
}
```

`supported_templates: ["*"]` means the package places no template constraint.

### 2.11.3 Dependency resolution

Resolution MUST complete before any materialization.

```text
Lua: request packages
        |
Package Service
        | resolve identity
        | select version
        | resolve dependency graph
        | validate compatibility
        v
Resolved Package Set
```

Algorithm — deterministic, and specified rather than promised:

1. Seed the constraint set from the workflow request, plus requirements declared
   by the resolved template and kits.
2. Maintain a work queue of unresolved identities, processed in sorted identity
   order.
3. For each identity, select the highest version satisfying all accumulated
   constraints ([[2.8 Templates]] §2.8.2).
4. Add the selected version's dependencies as new constraints.
5. If a newly added constraint invalidates an already-selected version,
   backtrack: reselect that identity at the next-highest satisfying version,
   visiting candidates in descending order.
6. Terminate when the queue is empty (success) or when an identity has no
   satisfying candidate (failure).

Backtracking MUST be bounded. Implementations MUST impose a documented step limit
and, on exceeding it, fail with `package.resolution.exhausted` rather than
running unbounded — a generator that hangs on Termux is worse than one that
refuses.

*Complexity: worst case exponential in the number of backtracking identities, as
for any version solver. In practice the graph is small and shallow; the step
limit bounds the pathological case. The developer docs MUST record the chosen
limit and its rationale.*

The dependency graph MUST be acyclic. A cycle MUST be reported with the full
cycle path, not merely detected.

### 2.11.4 Conflict reporting

A resolution failure MUST identify:

- the identity that could not be satisfied;
- every constraint acting on it, and which resource declared each;
- the versions that were considered and why each was rejected.

A conflict error that says only "no compatible version" is insufficient; the
workflow and the user need the constraint set to act.

### 2.11.5 Compatibility

Packages MAY declare compatibility against framework version, templates, kits,
platforms, other packages, and engine capabilities.

The engine validates and reports. Lua decides the response: another package,
another kit, another template, amended configuration, or termination. The engine
MUST NOT silently alter the requested project design.

### 2.11.6 Build integration

Packages declare build integration as **structured data**, not as build-system
text. The engine emits build files for the target build system from that data.

This keeps packages independent of any one build system and is what allows an
Android project to consume the same package declaration as a desktop one.

The generated project MUST contain enough emitted build configuration to rebuild
without the generator. Developers MUST NOT need knowledge of Package Service
internals.

### 2.11.7 Feature configuration

Features are declared with defaults and constraints. Configuration crosses as
structured data:

```json
{ "package": "package.squared.graphics",
  "features": { "vulkan": true, "opengl": false } }
```

Feature configuration MUST NOT depend on interactive prompts, environment
variables, or ambient generator state. Lua gathers; the engine validates and
applies. A feature whose constraints are unsatisfied MUST fail at resolution.

### 2.11.8 Offline availability

Packages MUST be resolvable from declared offline sources. The Package Service
MUST NOT implicitly require network access when an offline source is declared
authoritative.

If a required package is unavailable offline the engine MUST return a structured
resolution error. Network acquisition MAY exist as an optional extension, but MUST
NOT become an implicit requirement of the core generator
([[1.13 Repository invariant]]).

### 2.11.9 Integrity and validation

Packages SHOULD declare an integrity digest, verified before entering the
pipeline.

Validation covers envelope and type block correctness, identity and version
syntax, dependency availability and compatibility, framework/template/kit/platform
compatibility, required engine capabilities, build declaration well-formedness,
feature declarations, and integrity.

Invalid packages MUST NOT silently enter the pipeline.

### 2.11.10 Migrations

A package version change requiring more than file replacement MUST declare
migration rules, applied as part of the update transaction
([[2.7 Project generation model]] §2.7.11). A required but unavailable migration
MUST fail the update.

### 2.11.11 Reference package set

```text
package.squared.core
package.squared.graphics
package.squared.input
package.squared.audio
package.squared.gui
```
