# 2.12 Generated-project boundary

> [!info] Navigation
> Index: [[Specification Index]] · Parent: [[2 Generator architecture]]
> Prev: [[2.11 Packages]] · Next: [[2.13 Dependency graph]]

> [!note] Scope (D-006a)
> This section states the **guarantee**. The **mechanism** — ownership classes,
> provenance, conflict detection, ownership transfer — is
> [[2.7 Project generation model]] §2.7.10 and §2.7.12 and is not restated here.
> Keeping the guarantee separate from the mechanism means it can be checked
> without reading the generation model.

## Purpose

States, in checkable terms, what a generated project may never contain and may
never require. This is the promise `squared-pg` makes to every project it
creates.

## Content

### 2.12.1 Independence guarantee

A generated project MUST NOT require `squared-pg` to be present in order to:

- build;
- run;
- test;
- version control;
- relocate to another path, machine, or filesystem;
- share or distribute.

Deleting `squared-pg` entirely, or deleting the workspace's `.squared/` metadata,
MUST leave a fully working project. The only capability lost is the optional
regeneration and update workflow.

The generated project depends on the Squared framework. It MUST NOT depend on the
generator that created it.

```text
squared-pg  --generates-->  Generated Project  --consumes-->  Squared Framework
```

`squared-pg` creates the relationship. It is not part of it.

### 2.12.2 Leakage prohibition

A generated project MUST NOT contain:

- generator implementation source;
- generator service interfaces, headers, or symbols;
- references to the generator repository layout;
- generator-internal identifiers in build configuration;
- absolute paths to the generator installation;
- machine-specific paths of any kind;
- resources from `resources/generator/`;
- generator-internal state, handles, or temporary artifacts.

A generated project MAY contain generator-**authored** files. It MUST NOT contain
generator-**coupled** files. The distinction: an authored file works after the
generator is deleted; a coupled file does not.

### 2.12.3 Preservation guarantee

The generator MUST NOT destroy user work.

- A file the user authored is never overwritten.
- A file the generator seeded and the user then modified is never overwritten
  without explicit, per-operation authorization.
- A path the generator did not create is never deleted.
- Any operation that would violate the above is reported as a conflict and
  requires explicit action.

A blanket override mode MAY exist. It MUST be explicit, MUST NOT be the default,
and MUST report every path it overwrites.

### 2.12.4 Reproducibility guarantee

Given the recorded generation configuration and the same resource versions, the
generator MUST resolve the same resource set and SHOULD produce byte-identical
output where no timestamp- or ordering-sensitive content is involved
([[Spec conventions]]).

The workspace records what produced it, so this is checkable rather than assumed.

### 2.12.5 What the generator retains

After finalization the generator retains **nothing**: no lock, no handle, no
reference, no background state, no requirement to be run again.

The workspace metadata record is generator-*written* but user-*owned*. The user
may delete it, edit it, or commit it to version control.

### 2.12.6 Verification

The guarantee is testable and SHOULD be tested. A conformance check for a
generated project:

| Check | Method |
|---|---|
| Independence | build the project with the generator absent from the machine |
| Leakage | grep the workspace for the generator install path, repository paths, and internal symbol prefixes |
| Relocatability | move the workspace to a different path and rebuild |
| Metadata optionality | delete `.squared/` and rebuild |
| Preservation | modify a seeded file, regenerate, assert the modification survives |
| Reproducibility | generate twice from the same configuration and diff the resolved set |

These checks belong in the generator's own test suite. An untested guarantee is a
claim (see [[2.16 Architectural invariants]]).
